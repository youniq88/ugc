# Auto Merge Game (릴스용 자동 진행 머지 게임)

같은 단계 두 개가 닿으면 다음 단계로 합쳐지는 게임. 플레이어 조작 없이 요소들이 위쪽 관을 따라 줄지어 계속 내려오고, 넘치면 자동으로 재시작됩니다. 1080×1920(9:16) 캔버스라 인스타 릴스에 그대로 올릴 수 있습니다.

## 배포 주소

- https://merge-game-reels-buskers88-6629s-projects.vercel.app (Vercel, 프로젝트 `merge-game-reels`)
- 예: `?preset=fruits&ui=0` 을 붙이면 과일 프리셋을 UI 없이 바로 실행
- 배포는 파일을 통째로 올리지 않고, Vercel 빌드가 이 저장소의 `claude/progressive-merge-game-4ol028` 브랜치에서 `index.html` 을 받아 `public/` 에 놓는 방식입니다. 프로젝트 설정에 아래 두 줄이 들어 있으니, 새로 푸시한 내용을 반영하려면 같은 설정으로 다시 배포하기만 하면 됩니다.

```
빌드 명령: mkdir -p public && curl -fsSL -o public/index.html https://raw.githubusercontent.com/youniq88/ugc/claude/progressive-merge-game-4ol028/merge-game/index.html && curl -fsSL -o public/press.html https://raw.githubusercontent.com/youniq88/ugc/claude/progressive-merge-game-4ol028/merge-game/press.html && test -s public/index.html
출력 디렉터리: public
```

머지 게임과 규칙이 다른 프레스 모드는 `press.html` 로 따로 있습니다. 배포 주소 뒤에 `/press.html` 을 붙이면 열립니다.

## 실행

`merge-game/index.html` 을 브라우저(크롬 권장)로 열면 바로 시작됩니다. 서버 필요 없음.

- `?preset=planets` / `gems` / `jelly` / `myth` / `odyssey` / `dogs` / `cosmos` / `universe` / `weapons` / `wakppu` / `evolution` / `starlife` / `money` / `fruits` : 프리셋 선택 (URL 파라미터)
- `?ui=0` : 버튼 UI 숨긴 채 시작
- `?finale=lightning` / `?finale=arrow` / `?finale=moon` / `?finale=vortex` / `?finale=snap` / `?finale=annihilate` / `?finale=confetti` : 마지막 단계에 도달했을 때의 피날레를 지정 (기본값은 프리셋마다 다름)
- `?bounce=0.7` : 탄성(튕김 정도, 0~1)을 지정해 시작. UI의 "탄성" 슬라이더로도 실행 중에 바로 바꿀 수 있고, 프리셋을 바꾸면 그 프리셋 기본값으로 돌아갑니다
- `?speed=950` : 낙하 속도(관에서 내려오는 속도, px/s, 200~2000). UI "낙하" 슬라이더와 같은 값입니다
- `?rate=40` : 분당 발사 수(1분에 떨어뜨리는 개수, 10~1000). UI "발사" 슬라이더와 같은 값입니다
- `?gravity=2600` : 중력(px/s², 400~8000). UI "중력" 슬라이더와 같은 값입니다
- `?tubes=2` : 요소가 내려오는 관을 1~3개로 늘립니다(2개 이상이면 양옆 관이 사선으로 들어옵니다). UI "관" 슬라이더와 같은 값이고, 프리셋을 바꿔도 그대로 유지됩니다
- 단축키 `스페이스`/`P` 일시정지·재개, `H` UI 숨기기/보이기, `R` 녹화 시작/중지(시작하면 UI 자동 숨김, 끝나면 다시 표시), `Enter` 다시 시작

## 실제 크기 비율 (cosmos 프리셋)

cosmos 는 단계별 반지름이 실제 지름의 로그값에 비례합니다. 실제 지름이 3,474km 에서 384억km 까지 7자리수나 벌어져서 선형으로 맞추면 달이 0.00002px 이 되므로, 로그 간격으로 두어 실제 배율 차이가 클수록 화면에서의 단차도 크게 나도록 했습니다.

```
달           3,474 km         r=36
화성         6,779 km         r=42
지구        12,742 km         r=48
해왕성      49,244 km         r=61
목성       139,820 km         r=71
태양     1,391,400 km         r=93
아크투르스    3,560만 km       r=124
베텔게우스    12억 3,400만 km  r=157
블랙홀 M87*   384억 km        r=190
```

이미지의 `scale` 도 1.04 로 두어 그려지는 원의 지름이 충돌 반지름의 두 배와 정확히 맞습니다. 다른 프리셋은 1.08~1.12 라 살짝 겹쳐 보입니다.

## 관 개수

위에서 요소가 내려오는 통로(관)를 1~3개까지 늘릴 수 있습니다. UI 의 "관" 슬라이더나 `?tubes=2` 로 바꿉니다.

```
1개   수직 하나 (기본)
2개   좌우에서 30도 사선 둘
3개   수직 하나 + 좌우 30도 사선 둘 (2개일 때와 같은 각)
```

사선 관은 전부 그릇 한가운데를 겨눕니다. 겨눈 방향으로 그대로 쏘아 준 뒤 중력이 당기기 때문에, 양옆에서 들어온 줄기가 포물선을 그리며 가운데에서 만납니다. 만나는 높이는 낙하 속도와 중력에 따라 달라집니다 (기본값 기준 그릇 아래쪽 가운데).

- 관 하나는 입구 `m`(그릇 벽에 닿는 중심점), 진행 방향 `d`, 폭 방향 `n` 으로 정의합니다. 관 안에서의 위치는 축 방향 `u = (p-m)·d` 와 옆 방향 `s = (p-m)·n` 으로 봅니다. 관이 기울어져 있어 x 좌표만으로는 판정할 수 없기 때문입니다.
- `d` 는 입구에서 그릇 가운데를 향하므로 입구는 항상 벽에 수직입니다. 관 안에서는 `d` 방향 등속으로 내려오고 `s` 를 0으로 잡아 가운데선을 유지하다가, `u > 0` 이 되는 순간(입구 통과) 쏘아진 속도 그대로 자유낙하로 넘깁니다.
- 관이 몸체를 맡는 구간은 `u < r` 까지입니다. `u < 0` 에서 끊으면 반쯤 걸친 몸체가 그릇 벽 밖으로 판정돼 안쪽으로 튕겨 들어갑니다.
- 요소는 관을 하나씩 번갈아 가며 떨어집니다. 관이 늘어나면 동시에 여러 줄이 내려오므로 최대 발사 수도 관 개수만큼 같이 올라갑니다(1개 475/분 → 3개 1425/분).
- 게임오버 판정(`blocksTube`)도 관별로 따로 계산합니다. 위험선 한 줄로 보면 바깥 관이 아직 비어 있는데도 가운데가 찼다는 이유로 판이 끝납니다.
- 용기 테두리는 "가장 왼쪽 관의 바깥 벽 → 그릇을 크게 한 바퀴 → 가장 오른쪽 관의 바깥 벽" 한 줄과, 관 사이마다 칸막이(앞 관의 안쪽 벽 → 그릇 윗면 짧은 호 → 다음 관의 안쪽 벽) 한 줄씩으로 그립니다. 입구가 그릇에서 차지하는 반각은 `asin(85/490)`, 약 10도입니다.
- 클립(충돌 영역)용 경로는 기울어진 관 사각형들과 그릇 원을 같은 방향으로 그려 기본 nonzero 규칙으로 합집합이 되게 했습니다.
- 슬라이더를 움직이면 그 즉시 바뀌고, 관을 타고 내려오던 요소는 가장 가까운 새 관으로 옮겨 탑니다.

## 속도와 중력 조절

UI 오른쪽 위 슬라이더로 실행 중에 바로 바꿀 수 있고, 같은 값을 URL 파라미터로도 줄 수 있습니다. 탄성·낙하·발사·중력 네 개는 프리셋을 바꾸면 그 프리셋 기본값으로 돌아가고, 관 개수는 무대 설정이라 프리셋과 무관하게 유지됩니다.

- 낙하: 관 안에서 줄지어 내려오는 속도. 빠를수록 게임이 짧아집니다 (기본 950px/s 에서 40초 안팎)
- 발사: 1분에 몇 개를 떨어뜨릴지. 기본값은 관이 막히지 않는 최대치이고, 슬라이더를 그보다 올리면 값 옆에 "(최대)" 가 뜨면서 최대치로 유지됩니다. 최대치는 낙하 속도에 비례하므로 더 자주 떨어뜨리려면 낙하 속도를 먼저 올립니다
- 중력: 그릇 안에서 아래로 당기는 힘. 낮추면 느긋하게 떠다니듯, 높이면 묵직하게 쌓입니다 (관 안에서는 낙하 속도가 우선이라 중력 영향을 받지 않습니다)
- 관: 요소가 내려오는 통로 개수(1~3). 위의 "관 개수" 항목을 참고하세요

## 릴스용 영상 뽑기 (아이폰)

1. 사파리로 배포 주소를 열고 화면을 한 번 탭해 소리를 켭니다.
2. `● 녹화` 를 누르면 게임이 처음부터 시작되고 UI가 사라집니다.
3. 끝내려면 화면을 탭해 UI를 다시 띄우고 `■ 녹화 중지` 를 누릅니다.
4. 미리보기와 함께 `📲 사진 앨범에 저장` 버튼이 뜹니다. 누르면 iOS 공유 시트가 열리고 **"비디오 저장"** 을 선택하면 사진 앱 앨범에 mp4로 저장됩니다.
   (웹페이지는 앨범에 직접 쓸 수 없어서 공유 시트를 거치는 것이 iOS의 정식 방법입니다.)

데스크톱 크롬 등 공유 시트를 지원하지 않는 브라우저에서는 같은 버튼이 파일 다운로드로 동작합니다.

## 디자인 키트

요소 그래픽은 외부 무료 디자인 키트를 씁니다. 한 프리셋은 반드시 한 키트에서만 가져와 스타일을 통일합니다.

- planets / gems / fruits: **Microsoft Fluent Emoji 3D** (MIT 라이선스) 사용
  - 저장소: https://github.com/microsoft/fluentui-emoji (`assets/<이름>/3D/<파일>_3d.png`)
  - 이미지는 GitHub raw 주소에서 불러오고, 실패하면 jsDelivr CDN 주소로 재시도합니다. 처음 열 때 인터넷이 필요합니다.
- jelly: 단색 구미 젤리 9종. 무료 키트 중에 단색 구미 세트가 없어서 Higgsfield(GPT Image)로 한 세트를 렌더링한 뒤 배경을 제거해 512px 투명 PNG로 만들었습니다.
  - Higgsfield 미디어 저장소(CloudFront, CORS 허용)에서 불러옵니다. `KITS.gummy` 가 기본 URL, 항목의 `img` 가 파일명입니다.
- myth: 신화 생물 9종. 같은 방식으로 Fluent 3D 이모지풍(광택 3D 토이 스타일)의 캐릭터 시트를 먼저 한 장 렌더링해 스타일을 잡고, 그 시트를 참조 이미지로 9종을 각각 투명 배경으로 렌더링했습니다. `KITS.myth` 가 기본 URL입니다.
  - 원본 시안과 항목 PNG는 Higgsfield 계정의 생성 기록에 남아 있습니다. 다시 뽑거나 색을 바꾸려면 같은 프롬프트에 색만 바꿔 생성하면 됩니다.
- evolution / starlife / money: 진화 9종, 별의 일생 9종, 부의 단계 9종. myth 와 같은 방식(시트 한 장 → 시트를 참조로 9종 렌더링)이고 `KITS.evolution` / `KITS.starlife` / `KITS.money` 가 기본 URL입니다.
- odyssey: 오디세이아 9종. 광택 3D 가 아니라 굵은 먹선에 진한 채색을 올린 회화풍 코믹 일러스트(하데스 게임 느낌)로 시트를 잡고 같은 방식으로 9종을 렌더링했습니다. 오디세우스는 투구부터 발끝까지 전신, 아가멤논은 청동기 미케네 고증(멧돼지 엄니 투구, 검은 흉갑, 8자형 방패)입니다. `KITS.odyssey` 가 기본 URL입니다.
- dogs: 강아지 9종. 봉제 인형(솜인형) 스타일로, 인형 네 마리가 놓인 스타일 시트를 먼저 렌더링해 재질(보송한 천, 봉제선, 까만 구슬눈)을 고정하고 그 시트를 참조로 9종을 렌더링했습니다. `KITS.dogs` 가 기본 URL입니다.
- cosmos: 천체 8종. NASA 사진풍의 구체 렌더링으로 시트를 잡고 같은 방식으로 렌더링했습니다(마지막 블랙홀은 이미지가 아니라 코드로 그립니다). `KITS.cosmos` 가 기본 URL입니다.
- wakppu: 왁뿌볼 안에 든 과일 젤리 9종. 광택 나는 반투명 젤리로, 설탕 결정이 얹힌 표면과 밝은 하이라이트를 공통 규칙으로 잡았습니다. 비슷한 색이 이웃하지 않도록 포도, 딸기, 귤, 사과, 복숭아, 파인애플, 멜론, 수박, 거대 두리안 순서로 놓았습니다. `KITS.wakppu` 가 기본 URL입니다.
- weapons: 무기 9종. 레트로 16비트 픽셀아트 게임 아이템 스타일입니다(굵은 사각 픽셀 격자, 안티에일리어싱 없는 계단식 외곽, 두 단계 음영과 밝은 하이라이트 하나, 또렷한 어두운 테두리). 네 점짜리 스타일 시트를 먼저 잡고 그 시트를 참조로 9종을 렌더링했습니다. 픽셀아트, 플랫 벡터, 클레이, 수채 네 방향을 같은 소재로 뽑아 비교한 뒤 고른 안입니다(실사와 플라스틱 장난감 버전이 그 앞에 있었습니다). 칼날처럼 가는 것은 정사각 안에서 작게 보여서 `scale` 을 1.3 안팎까지 올려 키웠습니다. `KITS.weapons` 가 기본 URL입니다.
- universe: 우주 거대구조 7종 + 황금 건틀릿. 허블/제임스웹 사진풍으로 성운·은하·우주 거미줄을 렌더링했고, 지구와 태양은 cosmos 키트의 이미지를 그대로 씁니다. 마지막 건틀릿은 특정 영화 소품을 베끼지 않은 여섯 보석짜리 일반 디자인이고, 손가락을 튕기는 동작을 보여주려고 같은 장갑을 세 가지 자세(튕기기 직전 / 튕기는 순간 / 편 손)로 렌더링해 프레임으로 씁니다. 세 장은 같은 기준 영역으로 잘라야 프레임마다 손 크기와 위치가 튀지 않습니다. `KITS.universe` 가 기본 URL입니다.
- 검토했지만 쓰지 않은 키트: Kenney Planets / Puzzle Pack (CC0, https://github.com/shorepine/kenney 미러). 보석이 96px라 큰 단계에서 흐려져 제외.

프리셋 구성 (모두 9단계):

- planets: 초승달 → 그믐달 → 보름달 → 지구 → 토성 → 태양 → 별 → 빛나는 별 → 블랙홀(검은 구슬)
- gems: 진주 → 에메랄드 → 사파이어 → 자수정 → 루비 → 주황 다이아 → 파랑 다이아 → 젬스톤 → 왕관
- jelly: 빨강 콩 → 주황 물방울 → 노랑 하트 → 초록 별 → 민트 링 → 파랑 큐브 → 보라 꽃 → 분홍 물고기 → 하양 곰 (탄력 3배 체감: 반발 0.88 + 찌그러짐 흔들림)
- myth: 황금 알 → 아기 용 → 늑대 → 유니콘 → 그리핀 → 피닉스 → 드래곤 → 크라켄 → 제우스 (제우스가 나오면 번개 피날레)
- odyssey: 트로이 목마 → 로토스 꽃 → 키클롭스 → 아가멤논 → 키르케 → 세이렌 → 스킬라 → 카리브디스 → 오디세우스 (오디세우스가 나오면 화살 피날레)
- dogs: 치와와 → 포메라니안 → 웰시코기 → 비글 → 시바견 → 골든 리트리버 → 허스키 → 그레이트 데인 → 늑대 (늑대가 나오면 달빛 피날레)
- cosmos: 달 → 화성 → 지구 → 해왕성 → 목성 → 태양 → 아크투르스 → 베텔게우스 → 블랙홀 (블랙홀이 나오면 소용돌이 피날레). 크기가 실제 지름 비율을 따르는 유일한 프리셋입니다
- wakppu: 포도 → 딸기 → 귤 → 사과 → 복숭아 → 파인애플 → 멜론 → 수박 → 거대 두리안 (9단계. 앞의 다섯 가지를 섞어 떨어뜨립니다. 두리안이 나오면 왁스가 저절로 갈라지다 팡 터지는 피날레. 아래 왁뿌볼 항목 참고)
- weapons: 구석기 돌망치 → 청동 단검 → 강철 장검 → 석궁 → 화승총 → 기관총 → 로켓 → 폭탄 → 반물질 폭탄 (반물질 폭탄이 나오면 소멸 피날레, 하나도 남지 않습니다)
- universe: 지구 → 태양 → 태양계 → 오리온 성운 → 우리은하 → 국부은하군 → 라니아케아 초은하단 → 관측 가능한 우주 → 황금 건틀릿 (건틀릿이 나오면 핑거스냅 피날레). 실제 크기 차이가 20자리수를 넘고 건틀릿은 크기 자체가 없어서, 여기서는 다른 프리셋과 같은 등간격 반지름을 쓰고 실제 지름은 코드 주석에만 적어 두었습니다
- evolution: 세포 → 물고기 → 도마뱀 → 공룡 → 원숭이 → 스마트폰 보는 비즈니스맨 → 로봇 → AI → 은하
- starlife: 우주 먼지 → 운석 → 소행성 → 행성 → 적색거성 → 초신성 → 중성자별 → 블랙홀 → 은하
- money: 동전 → 지폐 다발 → 금괴 → 다이아몬드 → 금고 → 슈퍼카 → 저택 → 요트 → 로켓
- fruits: 체리 → 딸기 → 포도 → 귤 → 사과 → 복숭아 → 파인애플 → 멜론 → 수박

## 단계 요소 바꾸기

`index.html` 상단 `PRESETS` 에서 배열 순서 = 단계 순서입니다. 항목을 추가/삭제/교체하면 됩니다.

```js
{ r:36, img:"Cherries/3D/cherries_3d.png", glow:"#ff5a7a" },   // 키트(kit) 안의 경로
{ r:72, image:"https://.../my.png", glow:"#fff", scale:1.1 },   // 직접 URL
{ r:58, shape:"teardrop", colors:["#ffe08a","#b86a05"], glow:"#ffb02e" }, // 코드로 그리는 도형
```

- 새 키트를 쓰려면 `KITS` 에 기본 URL을 추가하고 프리셋의 `kit` 값을 바꿉니다.
- `r` 은 반지름(px). 단계가 올라갈수록 크게. 낙하 대상 단계는 관 폭(반폭 85px)보다 작아야 합니다.
- `scale` 은 PNG 여백 보정(기본 1.12). 그림이 충돌 원보다 작거나 크게 보이면 조절합니다.
- `drawR` 은 그림만 키우고 싶을 때 쓰는 별도의 반지름입니다. 충돌은 `r` 그대로, 그림은 `drawR` 기준으로 그립니다 (universe 의 건틀릿은 `r:190, drawR:380` 이라 충돌은 그대로면서 두 배 크게 보입니다).
- `frames` 는 동작 연출용 여벌 그림 목록입니다. 같은 규격의 PNG 를 순서대로 적어 두면 피날레에서 `b.frame` 으로 갈아 끼울 수 있습니다 (`frames[0]` 을 `img` 와 같게 두면 번호가 그대로 맞습니다).
- 화면에 이름 텍스트는 표시하지 않습니다. 하단 진행표는 기본 숨김이며 `SETTINGS.showLegend` 로 켤 수 있습니다.
- `SETTINGS` 에서 관 안 낙하 속도(`tubeSpeed`)와 요소 간격(`tubeGap`), 처음 몇 단계까지 떨어뜨릴지(`dropTiers`, 기본 1 = 항상 가장 낮은 단계만), 중력, 탄력(`restitution`), 점수/하단 진행표 표시 여부, 테두리 색을 바꿀 수 있습니다.
- 새 프리셋을 추가하면 우측 상단 드롭다운과 `?preset=` 에 자동으로 나타납니다.

## 피날레 (마지막 단계에 도달했을 때)

기본은 색종이 축하 연출입니다. 프리셋의 `finale` 값이나 `?finale=` 파라미터로 바꿀 수 있습니다: `lightning` 번개(신화 프리셋 기본), `arrow` 화살(오디세이아 프리셋 기본), `moon` 달빛(강아지 프리셋 기본), `vortex` 소용돌이(cosmos 프리셋 기본), `snap` 핑거스냅(universe 프리셋 기본), `annihilate` 소멸(무기 프리셋 기본), `durian` 두리안이 저절로 갈라지다 팡 터짐(왁뿌볼 프리셋 기본), `meteor` 운석이 떨어져 전부 불타고 작은 한 마리만 날아오름, `ash` 화산재가 쏟아져 전부 회색으로 굳음, `implode` 낮은 단계부터 수압에 찌그러져 터지고 마지막 단계만 남음. 뒤의 세 가지는 아직 어느 프리셋에도 붙어 있지 않습니다.

번개 피날레 순서 (제우스 등장 시점부터):

```
0.0초  제우스 탄생, 흰 섬광과 화면 흔들림
0.3초  하늘에서 제우스에게 큰 번개가 내리꽂힘 (천둥소리)
0.56초 제우스 손끝에서 가까운 요소부터 차례로 번개가 뻗어 나감 (총 1.15초 안에 전부 명중)
       맞은 요소는 0.6초 동안 달아올랐다가 숯처럼 그을리며 불똥과 함께 사라짐
2.4초  제우스만 남고 색종이와 충격파로 마무리
```

- 번개가 치는 동안에는 더 이상 합쳐지지 않습니다(`finaleBusy`).
- 그을린 그림과 불빛은 미리 한 번만 그려 두고 재사용합니다. 매 프레임 캔버스 필터·그림자 블러로 그리면 1080×1920 에서 프레임이 7배 넘게 느려져 녹화 영상이 끊깁니다.
- 피날레가 2.4초쯤 걸리므로 `tools/record.js` 는 클리어 후 5.5초를 더 녹화합니다.

화살 피날레 순서 (오디세우스 등장 시점부터):

```
0.0초  오디세우스 탄생, 흰 섬광과 화면 흔들림
0.22초 활시위를 당김 (몸이 뒤로 젖혀지며 떨리고, 팽팽하게 삐걱이는 소리)
1.0초  발사 (팅 소리). 화살 한 발이 가까운 요소부터 차례로 꿰뚫고 다음 표적으로 꺾여 날아감 (표적 하나당 최대 0.14초)
       맞은 요소는 황금빛 불꽃과 함께 움찔했다가 옆으로 쓰러지며 0.45초 만에 사라짐
약 2.6초 오디세우스만 남고 색종이와 충격파로 마무리 (구혼자 처단 장면)
```

- 화살은 `arrows` 배열로 관리하고, 지나간 자리에 황금빛 궤적이 잠깐 남았다 사라집니다.

달빛 피날레 순서 (늑대 등장 시점부터):

```
0.0초  늑대 탄생, 흰 섬광과 화면 흔들림
0.2초  오른쪽 하늘에 보름달이 떠오르고 화면이 푸른 밤으로 내려앉음
1.1초  늑대가 고개를 젖히고 길게 욺 (울음이 퍼지는 파문 세 겹)
1.5초  가까운 강아지부터 차례로 따라 욺 (총 1.5초 안에 전부, 마지막 한 마리까지 약 4.2초)
       울고 난 강아지는 빛 알갱이를 흘리며 위로 떠올라 달빛 속으로 사라짐
약 3.8초 늑대만 남고 색종이와 충격파로 마무리
```

- 달은 `moonSprite()` 로 한 번만 그려 두고 재사용합니다. 밤 색(`nightDim`)을 칠한 뒤에 그려야 달이 어두워지지 않습니다.

소용돌이 피날레 순서 (블랙홀 등장 시점부터):

```
0.0초  블랙홀 탄생, 흰 섬광과 화면 흔들림
0.26초 가까운 천체부터 차례로 나선을 그리며 끌려 들어감 (총 0.95초 안에 전부 시작)
       끌려가는 동안 점점 빨라지고 조석력으로 길게 늘어나다 사건의 지평선에서 사라짐
약 2.7초 전부 삼킨 뒤 블랙홀도 한 점으로 무너지고 화면이 검게 닫힘 (색종이 없이 그대로 끝)
```

- 끌려가는 동안에는 물리를 건너뛰고(`b.suck`) 피날레가 위치를 직접 잡습니다. 중력과 충돌을 그대로 두면 나선이 흐트러집니다.
- 마지막 검은 화면은 `voidDim` 이고, 이 프리셋만 승리 연출(색종이) 없이 끝납니다.

핑거스냅 피날레 순서 (건틀릿 등장 시점부터):

```
0.0초  건틀릿 탄생, 흰 섬광과 화면 흔들림
       그릇 한가운데로 미끄러져 와 멈추고 원래 크기까지 부풀어 오름 (그림은 다른 단계의 두 배)
0.24초 여섯 보석이 0.15초 간격으로 하나씩 켜짐 (보라·파랑·빨강·주황·초록·노랑 파문, 0.99초에 다 켜짐)
1.15초 손목을 뒤로 젖힘 (장갑이 삐걱이는 소리)
1.4초  딱 — 손가락이 튕겨 나가는 그림으로 바뀌고 손목이 반동으로 꺾임
       흰 섬광과 큰 흔들림, 충격파 세 겹, 쇳소리 → 폭발 → 저음 합창이 이어짐
1.5초  남은 것들 중 무작위 절반이 0.055초 간격으로 하나씩 재가 되어 흩어짐
1.95초 손을 편 그림으로 바뀌고 보석 빛이 식어감
이후    사라진 자리로 살아남은 절반이 무너져 내림 (물리를 11초 동안 더 굴림)
```

- 대상은 매번 무작위로 섞어서 정확히 절반(홀수면 올림)만 지웁니다. 건틀릿 자신은 남습니다.
- 재가 되는 중(`b.dust > 0.35`)에는 충돌을 건너뜁니다. 그대로 두면 사라지는 몸이 살아남은 것들을 밀어냅니다.
- 건틀릿은 `b.pin` 이 붙어 물리에서 빠지고 피날레가 위치를 직접 잡습니다. 그림이 충돌 원보다 훨씬 커서 그릇 가장자리에 있으면 잘리기 때문입니다.
- 무너지는 장면을 보여주려고 `physicsHoldMs` 를 11초로 늘립니다(기본 3초). 녹화도 클리어 뒤 5.5초를 더 기다립니다.
- 예약 연출(`later`)이 연출 안에서 또 예약을 겁니다. 그래서 `fxQueue` 는 실행할 항목을 먼저 빼내고 큐를 비운 뒤에 콜백을 돌려야 합니다.

소멸 피날레 순서 (반물질 폭탄 등장 시점부터):

```
0.0초  폭탄 탄생, 그릇 한가운데로 올라와 멈춤
0.26초 코어 충전: 고리 다섯 개가 0.2초 간격으로 밖에서 안으로 조여듦 (소리도 같이 높아짐)
1.46초 소멸: 화면이 하얗게 터지고 충격파 네 겹, 흔들림 44
1.54초 폭탄에서 가까운 순서대로 하나씩 하얗게 달아올랐다가 부풀며 빛알갱이로 흩어짐
약 2.7초 마지막에 폭탄 자신도 함께 사라짐 (하나도 남지 않음)
약 4.1초 잔광까지 빠지고 빈 그릇만 남음
```

- 흰 화면을 그대로 두면 정작 사라지는 장면이 안 보입니다. 번쩍인 직후 0.22초 만에 잔광(0.26)으로 내리고, 전부 사라진 뒤에야 0으로 뺍니다. 차오르는 속도와 빠지는 속도를 따로 두려고 `whiteFall` 을 씁니다.
- 하얗게 타는 모습은 `whiteSprite()` 로 한 번만 그려 두고 재사용합니다 (매 프레임 필터는 너무 느립니다).
- 고리에 `in: true` 를 주면 밖에서 안으로 조여듭니다 (기본은 안에서 밖으로 퍼짐).

## 효과음

외부 파일 없이 Web Audio 로 직접 합성합니다. 프리셋의 `sound` 값으로 테마를 고릅니다.

- `space` : 신비로운 종·패드 소리 (우주)
- `juicy` : 통통하고 촉촉한 플롭 소리 (과일)
- `crystal` : 유리 부딪히는 맑은 핑 (보석)
- `candy` : 통통 튀는 보잉, 뽀글 거품, 반짝 스파클이 섞인 귀엽고 달콤한 소리 (젤리)
- `epic` : 묵직한 북소리 타격, 합칠 때 금관과 합창처럼 부풀어 오르는 화음과 큰 북 (신화)
- `wax` : 굳은 양초 왁스가 와그자자작 부서지는 소리. 이 모드에서 나는 소리는 이것 하나뿐이고, 음정 있는 소리는 하나도 쓰지 않습니다 (왁뿌볼)
- `evolve` : 8비트 게임 타격음, 합칠 때 위로 올라가는 레벨업 아르페지오 (진화, 무기)
- `nova` : 묵직한 저음 쿵과 바람 소리, 합칠 때 부풀어 오르는 패드와 서브베이스 붐, 별가루 반짝임 (별의 일생, 우주)
- `cash` : 동전 짤랑 타격, 합칠 때 금전등록기 카칭 벨과 동전 쏟아지는 반짝임 (돈)
- `lyre` : 리라 현을 튕기는 맑은 소리와 손톱이 스치는 소리, 합칠 때 화음을 아래에서 위로 훑는 스트럼과 가죽 북, 뒤로 밀려가는 파도 (오디세이아)
- `plush` : 솜이 눌리는 둔한 착지와 천이 스치는 소리, 합칠 때 따뜻한 종소리 (강아지)
- `steel` : 쇠붙이가 쨍 부딪히는 소리, 합칠 때 모루를 때리는 타격과 종처럼 길게 남는 금속 배음 (지금은 어느 프리셋도 쓰지 않습니다)

부딪히는 소리는 세기와 단계(크기)에 따라 음량·음높이가 달라집니다. 합쳐지는 소리는 모든 프리셋 공통으로 **멜로디**를 따릅니다. 합칠 때마다 `MELODY` 의 다음 음이 나와 한 곡이 되고, 4음마다 `CHORDS` 의 베이스가 깔리며, 큰 단계는 한 옥타브 아래 음이 겹칩니다. 음색(패드/마림바/종)만 테마별로 다르고, 다시 시작하면 멜로디도 처음부터입니다. 멜로디는 반음 단위 숫자 배열이라 바꾸면 곡이 바뀝니다.
`SETTINGS.soundVolume` 으로 크기를 조절하고 0이면 무음입니다. 브라우저 정책상 화면을 한 번 탭해야 소리가 켜지며, `R` 녹화에는 소리도 함께 담깁니다. 새 테마를 만들려면 `THEMES` 에 `hit(tier, k)` / `merge(tier, m)` 함수를 추가하면 됩니다 (`m.f` 멜로디 음, `m.bass` 베이스, `m.low` 옥타브 아래).

## 자동 녹화 (tools/record.js)

- 헤드리스 크롬(Playwright)으로 게임을 처음부터 돌려 마지막 요소가 나올 때까지 소리와 함께 녹화하고, 인스타·유튜브 호환 mp4(h264 + aac)로 저장합니다.
- 게임 시간이 60초를 넘기거나 게임오버가 나면 그 판은 버리고 다시 촬영합니다(기본 4회 시도).
- 실행: `index.html`이 있는 폴더에서 `python3 -m http.server 8765` 로 띄운 뒤 `node tools/record.js <preset> <out.mp4> [시도 횟수] [최대 게임 초]`. 다른 주소면 `GAME_URL` 환경변수로 지정합니다.
- ffmpeg 가 설치되어 있어야 합니다. 요소는 항상 1단계만 떨어지고 `tubeSpeed 950 / tubeGap 48` 기준으로 보통 45~55초에 클리어되며, 60초를 넘기는 판은 자동으로 다시 촬영됩니다.

## 매일 자동 제작·업로드 (Claude Code Routine)

- claude.ai 의 Routine "머지 게임 릴스 매일 자동 제작·업로드" 가 매일 08:00 KST(23:00 UTC) 에 새 세션을 열어, 프리셋을 하루씩 돌아가며 고르고(planets → jelly → myth → odyssey → dogs → cosmos → universe → evolution → starlife → money → gems → fruits), Higgsfield 샌드박스에서 이 저장소의 `index.html` + `tools/record.js` 로 녹화한 뒤 mp4 를 Higgsfield CDN 에 올리고, Zapier 로 YouTube(쇼츠, 공개)와 Instagram(릴스)에 캡션 하나와 함께 올립니다. 캡션과 제목은 영어 한 줄로, 해시태그 없이, 결말을 밝히지 않고 끝까지 보고 싶어지게 씁니다.
- Routine 세션이 Higgsfield 와 Zapier 도구를 쓰려면 claude.ai Routine 설정에서 두 커넥터를 붙여 두어야 하고, Zapier 에서 YouTube 와 Instagram for Business 계정을 연결해 두어야 합니다. Instagram 은 크리에이터/비즈니스 계정이 페이스북 페이지에 연결되어 있어야 Zapier 가 계정을 찾습니다.
- 결과(프리셋, 영상 URL, 업로드 링크 또는 오류, 캡션)는 Routine 실행 요약과 푸시 알림으로 옵니다.

## 왁뿌볼 (wakppu)

실제 왁뿌볼(왁스 뿌시기 볼)을 옮긴 모드입니다. 말랑한 과일 젤리에 녹인 양초를 부어 굳힌 장난감이고, 누르면 굳은 왁스층이 잘게 깨집니다. 깨지는 소리가 주인공이라 다른 소리는 최대한 비워 두었습니다.

### 네 번 부딪혀야 합쳐진다

같은 단계끼리 닿아도 바로 합쳐지지 않습니다. 몸체마다 `crack` 값을 들고 다니고, 닿을 때마다 양쪽이 같이 한 단계씩 깨집니다.

```
1. 첫 번째 접촉  금이 거미줄처럼 번지고 잔 조각 네 개가 떨어져 나갑니다 (crack 1)
2. 두 번째 접촉  금이 촘촘해지고 조각 아홉 개가 더 떨어집니다 (crack 2)
3. 세 번째 접촉  껍질이 통째로 사라지고 젤리 알맹이가 드러납니다 (crack 3)
4. 네 번째 접촉  비로소 합쳐집니다
```

한 번 닿을 때 여러 겹이 한꺼번에 깨지지 않도록 몸체마다 `crackAt` 에 마지막으로 깨진 시각을 적어 두고 180ms 안에는 다시 깨지지 않게 막습니다. 양쪽 모두 `crack` 이 3이 되어야 합쳐지므로, 서로 다른 짝을 만나 진도가 어긋난 경우에도 규칙이 어긋나지 않습니다.

### 껍질 그리는 법

껍질은 그림 파일이 아니라 캔버스로 그립니다. 알맹이 그림의 실루엣을 스무 방향으로 조금씩 밀어 그려서 두께만큼만 부풀린 뒤(`k*0.055`), 그 안쪽만 흰 왁스로 채웁니다(`source-in`). 알맹이 바깥으로 삐져나온 얇은 띠가 그대로 흰 테두리가 되어서 따로 선을 그리지 않아도 막을 씌운 것처럼 보입니다.

### 튀는 왁스 조각

껍질이 깨진 자리에서 조각이 사방으로 팍 튀어 나갑니다. 한 번 깨질 때마다 세 종류를 같이 뿌립니다.

```
1. 큰 조각    반지름에 비례해 서너 개. 각진 다각형으로 그리고 제각기 다른 속도로 돕니다
2. 부스러기   여섯에서 열댓 개. 더 넓은 각도로 초속 1,100px 까지 튀어 나갑니다
3. 흰 가루    깨진 자리에 잠깐 머물다 빨리 사라지는 네 개
```

조각 모양은 시작할 때 다섯에서 여섯 꼭짓점짜리 다각형 네 가지를 만들어 두고 돌려 씁니다. 매번 새로 만들지 않습니다. 깨진 겹수에 따라 세기가 달라져서, 껍질이 통째로 벗겨지는 세 번째가 첫 번째의 두 배로 튀고 이때만 흰 링이 한 겹 퍼집니다.

조각은 그릇 벽에 맞고 튕깁니다(감쇠 0.7). 두리안이 터질 때 나오는 조각 110개만 `free` 표시를 달아 벽을 무시하고 화면 밖까지 날아갑니다.

실제 rAF 루프에서 16초를 재 보면 프레임 평균 0.46ms, 최대 4.5ms, 동시에 떠 있는 파티클은 최대 271개입니다.

금은 충격점에서 여덟에서 열 갈래로 뻗고 각 갈래는 중간에서 한 번 더 갈라집니다. 밝은 선을 먼저 긋고(`source-atop`) 그보다 가는 폭으로 지우면(`destination-out`) 갈라진 틈에 빛나는 가장자리가 남습니다. 떨어져 나간 조각도 같은 방식입니다.

껍질 그림은 단계 세 개 × 무늬 두 개로 미리 구워 둡니다(`bakeShells`). 경기 중에 처음 만들면 큰 단계에서 20ms 넘게 끊기기 때문에, 그림이 다 받아진 직후에 한꺼번에 만들어 둡니다.

### 소리

발진기를 전혀 쓰지 않습니다. 시작할 때 0.7초짜리 알갱이 버퍼를 한 번만 구워 두고(`makeCrunchBuf`), 재생 속도와 필터만 바꿔 가며 잘라 씁니다(`crunch`). 음정을 만들 부품이 없으므로 유리나 실로폰 같은 소리가 나지 않습니다.

```
1. 와       재생 속도 0.34에서 0.42로 느리게 깐 아주 짧은 저역 충격
2. 그작     대역통과로 중저역을 살린 씹히는 구간. 여기가 제일 큰 소리입니다
3. 자자작   재생 속도 1.1에서 1.3으로 빠르게, 고역만 통과시킨 흩어지는 꼬리
4. 붕괴     3단계는 0.2초 뒤 두 번째 무더기가 한 번 더 쏟아집니다
5. 합체     소리를 내지 않습니다
6. 부딪힘   부딪히는 소리도 내지 않습니다. 초당 수십 번 울려서 깨지는 소리를 덮어 버립니다
```

`SFX` 안에 찌그러져 터지는 소리인 `crack()` 이 이미 있어서, 껍질 깨지는 소리는 `shellCrack(stage, tier)` 이라는 다른 이름으로 두었습니다. 같은 이름으로 두면 뒤에 정의된 쪽이 이겨서 엉뚱한 소리가 납니다.

큰 왁뿌볼일수록 전체 음이 낮아지고, 깨질 때마다 음높이를 5% 안에서 흔들어 같은 소리가 반복되지 않게 했습니다.

### 크기

반지름을 32, 41, 52, 64, 76, 94, 116, 145, 260으로 잡았습니다. 다른 9단계 프리셋의 마지막이 190이니 두리안이 그보다 한참 큽니다. 수박(145)에서 두리안(260)으로 넘어갈 때 넓이가 세 배 넘게 뛰기 때문에 마지막 한 번이 유난히 커 보입니다.

관 폭이 85라서 5단계(복숭아 76)까지 관을 통과합니다. 프리셋에 `dropTiers: 5` 를 두어 이 다섯 가지를 섞어 떨어뜨리고, `rate: 150` 으로 분당 150개까지만 떨어뜨립니다. 탄성은 `physics: { restitution: 0.3 }` 으로 기본값 0.55보다 낮췄습니다. 왁스를 씌운 공이라 통통 튀지 않는 편이 맞기도 하고, 덜 튀어야 관 입구까지 차오르지 않습니다. 세 값 모두 프리셋 안에 있고 `SETTINGS` 기본값보다 우선합니다.

### 왜 이렇게 잡았나

네 번씩 부딪혀야 합쳐지니 같은 그림을 얻는 데 보통 프리셋의 네 배 가까운 시간이 듭니다. 처음에는 반지름 52~292에 1단계만 떨어뜨렸는데, 180초를 돌려도 두리안까지 가지 못했습니다. 네 번 모두 그릇이 먼저 넘쳤고(180초 동안 게임 오버 다섯 번), 제일 멀리 간 것이 여덟 번째 수박이었습니다.

세 가지를 함께 바꿔서 풀었습니다. 떨어뜨리는 종류를 다섯으로 늘리고, 사다리 전체를 줄이고, 탄성을 0.3으로 낮췄습니다. 탄성이 제일 크게 들었습니다. 사다리만 줄였을 때는 여덟 번 중 두 번 넘쳤는데, 탄성을 0.55에서 0.3으로 내리자 여덟 번 모두 넘치지 않았습니다.

지금 설정으로 열두 번 돌린 결과입니다. 열두 번 모두 두리안이 나왔고, 그중 열한 번은 도중에 게임 오버 없이 갔습니다. 그 열한 번이 29.7, 37.4, 40.0, 40.4, 41.2, 43.9, 45.6, 49.2, 49.3, 50.0, 54.4초로 평균 43.7초입니다. 녹화 스크립트(`tools/record.js`)가 한 판에 62초까지 기다리므로 여유가 8초쯤 남고, 게임 오버가 난 판은 record.js 가 버리고 다시 찍기 때문에 영상에는 남지 않습니다.

측정에는 `tools` 밖의 임시 스크립트를 썼습니다. `requestAnimationFrame` 을 끄고 `loop()` 를 직접 돌리면서 `render()` 를 비워 두면 3분짜리 한 판을 몇 초 만에 굴려 볼 수 있습니다.

### 두리안 피날레

마지막 두리안이 나오면 `durianFinale` 이 돌아갑니다. 부딪히는 것과 상관없이 왁스가 저절로 갈라집니다.

```
1. 0.35초   한 겹 갈라지고 조각 여덟 개가 떨어집니다
2. 1.05초   두 겹째 갈라지고 조각 열일곱 개가 흩어집니다
3. 1.75초   껍질이 통째로 사라지고 알맹이가 드러납니다
4. 2.30초   터지기 직전에 부르르 떨립니다
5. 2.85초   팡. 화면이 하얗게 번쩍이고 링 네 겹이 퍼지며 색종이와 왁스 조각 아흔 개가
           사방으로 터집니다. 그릇에 남아 있던 다른 왁뿌볼도 이때 한꺼번에 깨지면서
           바깥으로 밀려납니다
6. 3.2초부터 양옆과 위에서 색종이가 세 번 더 쏟아집니다
```

터지는 소리도 음정 없이 만들었습니다. 알갱이 버퍼를 아주 느리게(재생 속도 0.3) 깔아 터지는 순간을 만들고, 그 위에 0.55초와 0.85초짜리 고역 층을 겹쳐 조각이 멀리까지 흩날리게 했습니다. 0.13초 뒤부터는 짧은 고역 잡음 열 개가 이어지며 반짝이는 부스러기 소리를 냅니다.

## 프레스 모드 (press.html)

머지 게임과 규칙이 완전히 달라서 파일을 따로 두었습니다. 합치는 게 아니라 **쪼개는** 게임입니다.

가운데 압착기가 물 때마다 입 안에 든 공이 터지면서 하나가 둘이 됩니다. 개수가 두 배로 늘 때마다 공 색이 다음 색으로 넘어가서, 새로 생긴 색이 화면의 절반을 차지합니다. 늘어난 만큼 원이 커지고, 목표 개수에 닿으면 압착기가 끝까지 내리찍으며 전부 터집니다.

### 여는 법

`merge-game/press.html` 을 브라우저로 열면 바로 시작됩니다.

```
?cycle=600   한 번 물었다 벌리기까지 걸리는 시간 (ms, 400~2000)
?ball=20     공 반지름 (px, 10~40)
?goal=460    이만큼 되면 피날레
?ui=0        버튼 UI 없이 시작
```

### 압착기

양옆 벽이 레일을 타고 가운데로 미끄러져 들어옵니다. 위아래는 양쪽 벽에 붙은 귀퉁이 브래킷만 있고 가운데가 뚫려 있어서, 공이 위아래로 드나듭니다. 다 닫히면 브래킷끼리 맞물려 한 덩어리처럼 보입니다.

한 주기는 이렇게 흘러갑니다.

```
1. 0.00~0.16  양옆 벽이 가운데로 들어옵니다
2. 0.14       무는 순간. 이때 입 안에 있던 공이 전부 터집니다
3. 0.16~0.26  다 닫힌 채로 물고 있습니다
4. 0.26~0.46  다시 벌어집니다
5. 0.46~1.00  벌린 채로 기다립니다. 입 안에 물 게 하나도 없으면 여기서 계속 기다립니다
```

무는 판정을 매 프레임 "벽 사이 간격이 공보다 좁은가"로 두면 안 됩니다. 그 창이 한 프레임보다 짧아서 그냥 지나쳐 버립니다. 주기의 0.14 지점을 넘어가는 프레임에 딱 한 번 부르는 방식으로 두어야 매번 확실히 뭅니다.

### 공이 압착기를 찾아가는 법

공은 늘 압착기 입 쪽으로 방향을 틉니다. 뚫린 폭 안에 있으면 입 한가운데를, 옆구리에 있으면 먼저 틀 위아래 바깥을 겨냥합니다. 개수가 적을수록 세게 틀어서(초당 5까지) 금방 물리고, 많아지면 약하게(1.3) 둡니다.

겨냥점을 y 좌표로 나누면 경계에서 두 목표 사이를 오가며 제자리에 멈춰 버립니다. x 좌표(뚫린 폭 안에 있는가)로 나눠야 합니다.

어딘가에 끼어 0.7초 넘게 거의 멈춰 있으면 아무 방향으로 한 번 차 줍니다. 그래야 구석에서 영영 못 빠져나오는 일이 없습니다.

### 크기와 시간

```
공 반지름 20, 처음 원 반지름 330, 압착기 300×284, 목표 460개, 주기 600ms
원은 sqrt(개수 × 공넓이 / 0.8) 만큼 커집니다. 빽빽할수록 입이 자주 차서 빨리 불어납니다
틀 모서리와 원 사이에는 공 지름의 두 배쯤 틈을 둬야 구석에 끼지 않습니다
```

한 판이 36~39초쯤 걸립니다. 1개에서 시작해 9초에 27개, 19초에 139개, 35초에 443개까지 갑니다. 녹화 제한 62초 안에 넉넉히 들어옵니다.

### 소리

압착기 소리만 씁니다. 벽이 들어올 때 유압 소리, 다 닫힐 때 쇠 부딪히는 소리, 터질 때 한 번에 몇 개가 터지느냐에 따라 두께가 달라지는 파열음입니다. 공끼리 부딪히는 소리는 0.1초에 세 번까지만 내보내 뭉개지지 않게 막았습니다.

### 녹화

`tools/record.js` 를 그대로 쓸 수 있습니다. 주소만 바꿔 주면 됩니다.

```
GAME_URL=http://localhost:8765/press.html node record.js press out.mp4 5 62
```

`TIERS` 와 `imgCache` 를 빈 값으로, `overSince` 를 늘 0으로 두어서 record.js 가 보는 값이 전부 있습니다. 이 모드에는 게임 오버가 없습니다.
